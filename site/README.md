# Сайт конспектов потока

Предметы, темпланы, литература, расписание, конспекты по каждой теме и «Вопрос дня».

**Кто что видит**

| | Гость | После регистрации |
|---|---|---|
| Предметы, темплан, литература, расписание | да | да |
| Вопрос дня | вопрос | вопрос и ответ |
| Конспект: «Кратко» и оглавление | да (`public_summary` в `site.yaml`) | да |
| Конспект целиком, термины, «Проверь себя» | нет | да |

Закрытые части не попадают в страницу для гостя вообще, их не достать через «Просмотр кода».

Контент лежит в папке `content/` обычными текстовыми файлами, без админки.
Регистрация, вход и сброс пароля сделаны через Supabase Auth (email + пароль).

Стек: Next.js 15, Supabase Auth. Хостинг — Vercel. На старте всё бесплатно.

## Как опубликовать (≈30 минут, без терминала)

### Шаг 1. Сайт на Vercel
1. vercel.com → Add New → Project → Import репозитория `my-gemini-bot`.
2. **Root Directory:** `site`. Deploy.
3. Скопируйте адрес сайта, например `https://konspekty.vercel.app`. Он нужен дальше.

Без шагов 2–4 сайт уже работает, но кнопок регистрации нет, а конспекты закрыты для всех.

### Шаг 2. Supabase (вход и регистрация)
Нужен **отдельный проект**, не тот, что для CRM UMED: это ваш личный бренд, данные нельзя смешивать.

1. supabase.com → New project. Регион **Central EU (Frankfurt)**.
2. **Authentication → URL Configuration:**
   - Site URL: адрес сайта из шага 1;
   - Redirect URLs: добавьте `https://ВАШ-АДРЕС/**`.
3. **Authentication → Sign In / Providers → Email:** включено. **Confirm email** рекомендую на старте
   **выключить**: человек регистрируется в одно действие, без письма. Минус: если ошибся в email,
   сбросить пароль не сможет.
4. **Project Settings → API:** скопируйте Project URL и ключ `anon` (или `publishable`).
5. Vercel → проект → Settings → Environment Variables:
   - `NEXT_PUBLIC_SUPABASE_URL` — Project URL;
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY` — ключ.
6. Vercel → Deployments → последний → **Redeploy**. Появятся кнопки «Войти» и «Регистрация».

### Шаг 3. Почта для писем (обязательно для сброса пароля)
Встроенная почта Supabase отправляет письма **только участникам команды проекта** и не больше 2 в час.
Студенты письмо для сброса пароля не получат. Нужен свой SMTP — бесплатный подойдёт.

Вариант на старте — **Brevo** (brevo.com, бесплатно до 300 писем в день, свой домен не обязателен):
1. Зарегистрируйтесь → Senders, Domains → добавьте адрес отправителя и подтвердите его.
2. SMTP & API → SMTP → создайте SMTP key.
3. Supabase → Authentication → Emails → **SMTP Settings** → Enable custom SMTP:
   - Host `smtp-relay.brevo.com`, Port `587`;
   - Username — логин SMTP из Brevo, Password — SMTP key;
   - Sender email — подтверждённый адрес, Sender name — название сайта.
4. Там же поднимите лимит писем в час (Authentication → Rate Limits), если упрётесь.

Когда появится свой домен, подключите его в Brevo: письма будут реже попадать в спам.

### Шаг 4. Тексты писем на русском
Supabase → Authentication → Emails → Templates. Ссылки должны вести на `/auth/confirm` с `token_hash`:
так они открываются в любом браузере, в том числе из приложения Gmail на телефоне.

**Reset Password** — тема: `Сброс пароля`
```html
<h2>Сброс пароля</h2>
<p>Кто-то (надеемся, вы) запросил сброс пароля. Нажмите, чтобы задать новый:</p>
<p><a href="{{ .SiteURL }}/auth/confirm?token_hash={{ .TokenHash }}&type=recovery&next=/reset">Задать новый пароль</a></p>
<p>Если вы ничего не запрашивали, просто удалите это письмо.</p>
```

**Confirm signup** (нужно, только если Confirm email включён) — тема: `Подтвердите email`
```html
<h2>Почти готово!</h2>
<p>Нажмите, чтобы подтвердить email и открыть все конспекты:</p>
<p><a href="{{ .SiteURL }}/auth/confirm?token_hash={{ .TokenHash }}&type=email">Подтвердить email</a></p>
```

### Проверка после запуска
1. Зарегистрируйтесь с личной почты → конспект открывается целиком.
2. Выйдите → конспект снова закрыт, видно только «Кратко».
3. «Забыли пароль?» → письмо пришло → ссылка открывает «Новый пароль» → войти с новым паролем.

Vercel публикует ветку `main`: изменения появляются на сайте после слияния pull request.
Это отдельный проект Vercel, CRM он не затрагивает.

## Как устроен контент

```
content/
  site.yaml                 название, «обо мне», дисклеймер, ссылки
  schedule.yaml             расписание по дням недели
  subjects/
    <предмет>/
      subject.yaml          название, темплан, литература, преподаватели
      notes/
        <тема>.md           конспект одной темы
```

**Темплан** (`subject.yaml` → `plan`): у каждой темы есть номер, дата, название и тип.
Поле `note: <имя файла>` связывает тему с конспектом, и в темплане появляется ссылка «Открыть →».

**Вопрос дня** выбирается сам из всех вопросов «Проверь себя» по всем конспектам и меняется в полночь
по Бишкеку. Чем больше конспектов, тем разнообразнее вопросы.

**Конспект** (`notes/<тема>.md`) всегда имеет одинаковую структуру:

| Блок | Где задаётся |
|---|---|
| Кратко (5–7 тезисов) | `summary` в шапке файла |
| Основной текст с таблицами | тело файла (Markdown) |
| Выделение маркером | `<mark>текст</mark>` |
| Врезки | `> [!key]` главное · `> [!mnemo]` мнемоника · `> [!clinic]` клиника · `> [!warn]` частая ошибка · `> [!exam]` спрашивают на экзамене |
| Ключевые термины | `terms` в шапке |
| Проверь себя (ответ скрыт) | `questions` в шапке |
| Источники | `sources` в шапке |
| Статус | `status: черновик` или `проверено` |

## Проверка контента

Перед каждой публикацией запускается `scripts/check-content.mjs`. Он проверяет темпланы и конспекты:
номера тем не повторяются, даты в нужном формате, у каждой ссылки на конспект есть файл, у вопросов
есть ответы и т. д. Если есть ошибка, Vercel не опубликует сайт и покажет в логе понятное сообщение
по-русски. Старая версия сайта при этом продолжит работать.

Шаблоны предмета и конспекта лежат в `templates/`.

## Процесс подготовки конспекта

1. Жанетта присылает темплан (фото, PDF или текст) и материалы по теме: лекции, презентации, главы учебника.
2. Claude собирает конспект в этом формате **своими словами**, без копирования чужих текстов, со статусом `черновик`.
3. Жанетта проверяет факты по лекции и учебнику, после этого ставится `проверено`.
4. Слияние pull request публикует конспект на сайте.

Статус `проверено` ставит только человек. Конспекты подписаны именем автора, и ошибка в медицинском
материале бьёт по личному бренду.
